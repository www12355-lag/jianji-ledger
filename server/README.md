# 简记好友服务 · 2.4

当前部署：`https://47.94.4.152`，阿里云北京 ECS。面向少量朋友的内测，默认最多 20 个账号；注册需要管理员提供的私密注册口令。账号恢复码在注册或恢复时只显示一次，请用户自行保存。

## 数据保存

- 本地完整账本、图片、草稿仍在原手机，不进行账号云同步。换机仍需要原有账本备份/恢复功能。
- 云端保存好友账号、密码哈希、恢复码哈希、登录令牌哈希、好友关系，以及用户主动分享给指定好友的日报/周报/月报汇总和鼓励。
- 分享默认隐藏金额和分类名，前后端都清除隐藏数据及不在白名单中的字段。金额可由本人选择显示。分享不会上传账目列表、商户、备注、账户或照片。
- 数据库：`/var/lib/jianji/friends.sqlite3`，SQLite 文件，仅服务账号可读写。API 只监听 `127.0.0.1:8787`，由 Nginx 443 代理；8787 不是数据库端口，也不对公网开放。
- 删除好友撤销双方已有分享权限；重新添加也不会恢复旧授权。同一周期重新分享会替换内容和接收好友，并清除原鼓励。已被他人保存的截图无法撤回。
- Android 登录状态经 Keystore AES-GCM 加密保存；网页使用 sessionStorage。退出登录撤销服务器令牌，账号恢复使其他设备登录失效。

## 服务器运维

源代码 `/opt/jianji/app.py` 和 `/opt/jianji/backup.py`，配置 `/etc/jianji/config.json`（含 `enrollment` 注册口令、`maxUsers` 和允许来源）。注册口令不能放进前端、APK、Git 或公开网页。更新配置后重启服务。

```sh
systemctl status jianji --no-pager
curl --fail https://47.94.4.152/health
systemctl restart jianji
journalctl -u jianji -n 30 --no-pager
systemctl list-timers jianji-certbot.timer jianji-backup.timer --no-pager
```

安全组放行 TCP 80（ACME 证书验证）和 443（HTTPS）；80 仅提供验证目录，其他路径 404。禁止向公网开放 8787。既有 SSH 访问策略由服务器管理员维护。

Let's Encrypt IP 短期证书存于 `/etc/letsencrypt/live/jianji-ip/`，Certbot 位于 `/opt/jianji-certbot/bin/certbot`，每天两次检查续期，成功后自动重载 Nginx。首次签发和 `renew --dry-run` 均已验证。IP 改变需要修改 `social-app.js` 的服务地址和 Nginx，重新签发证书并重新构建 APK。部署脚本 `https.sh` 用于首次安装，请勿为了更新代码直接重跑签发脚本。

```sh
/opt/jianji-certbot/bin/certbot renew --dry-run
systemctl start jianji-certbot.service
nginx -t
```

## 备份与恢复

每天 03:00 在 `/var/lib/jianji/backups/` 生成一致性 SQLite 快照，保留最近 14 份，快照移除登录令牌，恢复后需重新登录。可用以下命令立即备份：

```sh
systemctl start jianji-backup.service
journalctl -u jianji-backup -n 8 --no-pager
```

**这些备份仍在同一块服务器磁盘，不能防止实例释放或磁盘丢失。** 管理员需要另行将备份下载到电脑或存入独立存储，并妥善保护这些含用户资料的文件。更换机器时同时保留配置、源代码，重新配置 HTTPS。

恢复前停止 `jianji`，保留当前数据库及 WAL/SHM 文件到独立目录，再用选定的备份替换数据库，校正 `jianji:jianji` 所有者和 0600 权限，启动服务并验证健康与登录。不要在运行时直接覆盖数据库文件。

控制台截图显示试用有效期至 **2027-01-13 09:00**，实际额度与计费以阿里云控制台为准；到期前安排续用或迁移和异地备份。

## 验证

Python 3.11：在本目录运行 `python -m unittest -v test_api`。覆盖认证、恢复码、权限隔离、撤回、删除好友后授权失效、重新分享、数据库持久化、CORS 和输入限制；测试使用临时数据库。

当前部署已用合成数据验证公网证书、Android WebView 登录和加密登录状态、好友确认、分享、鼓励和非本人无法撤回他人报告。

## 2.3 账号与私聊

新增 `profiles`、`messages`、`conversation_reads` 表，升级启动自动创建，保留原账号、好友与报告。消息仅当前好友可读写；双方聊天保存在服务器，HTTPS 加密传输但不是端到端加密。每条最多 2000 字，每分钟最多 30 条，客户端消息 ID 实现重试去重，历史按 50 条分页，打开最新消息后更新已读位置。删除好友会禁止聊天与历史读取；数据库保留历史，重新加好友后可再次查看。

账号资料支持昵称、个人介绍和四种头像颜色，账号名不变。内测账号名额及注册口令延用原配置。

自动分享在手机端执行，完整账本仍留在手机；服务器不能在手机关闭时生成新的消费汇总。每次记账保存后、联网恢复或重新打开应用时更新所选当前周期。默认关闭、明确选定接收好友，公开内容按本人设置控制。排行榜当前仅有说明入口。

后端权限与分页测试新增 2 组，运行 `python -m unittest -v test_api`；目前共 8 组通过。

## 2.4 好友备注和发送确认

`friend_notes(owner,friend,remark)` 保存每个人自己的好友备注；GET/PATCH `/v1/friends/{id}` 均要求当前好友关系。备注只有设置者可以读取，删除好友清除双方备注。好友资料仅返回昵称、账号、头像颜色和自己的备注，不返回私人介绍、邀请码、恢复码或认证信息。

消息历史仅向发送者返回客户端消息标识，用于确认回执丢失的发送；收到的消息不带这一字段。报告发布成功返回经过白名单处理的汇总和服务器时间，用于立即更新已确认的分享展示，权限规则继续沿用。

原注册口令配置保留，升级不清空账号、好友关系或账目汇总。本轮后端测试共 10 组通过，覆盖好友资料权限、备注隔离与持久化、消息确认和报告隐私。

## 2.5 云备份、挑战与分摊

升级需同时部署 `app.py` 和 `features.py`；启动自动创建新表，保留原账号及数据。新增接口 `/v1/cloud`、`/v1/cloud/content`、`/v1/challenges`、`/v1/aa`，全部要求现有登录令牌。

云备份只存客户端加密信封，不接收密码或明文账本。每个账号保留一份最大 20 MB 的密文；版本递增，删除保留空的版本记录，避免删除后重新创建导致旧设备误覆盖。每账号每小时最多 12 次写入或删除。大请求读取前验证令牌，最多 1 个云备份上传／下载同时执行。Nginx 仅云备份上传接口允许 21 MB 请求，其余仍为 32 KB；预检缓存 600 秒，入口限流返回可跨域读取的 429。数据库端口继续仅监听本机。

挑战仅保存加入状态及当天日期，按挑战已加入成员展示排行，不接受过去／未来签到。删除好友会移除其在对方发起的挑战与在线分摊中的查看资格。AA 金额使用整数分，合计严格校验；参与好友先接收再查看完整单据，结算最多到自己的份额。结算客户端标识用于重试去重，发起人确认收到，服务不执行真实转账。

完整云备份密文也包含在每日服务器数据库快照中。用户删除后当前数据库不再提供下载，旧快照按 14 份保留政策轮换。管理员仍需异地保存数据库快照。使用 `python -m unittest -v test_api test_features` 运行 13 组测试，另已通过公网 HTTPS 和 Android WebView 两账号联调。
